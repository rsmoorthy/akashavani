# 0006 — Two OTA paths

## Context

The device may be on a site LAN or only reachable through the cloud. Bench work
needs a quick upload path. Field updates need to be initiated remotely.

## Decision

Support both:

- **ArduinoOTA** for LAN/bench maintenance;
- **HTTP pull** from the cloud server for remote updates.

Both write to the inactive OTA slot. The server tracks releases, channels,
checksums and metadata. The device checks with its current version and downloads
with its device token.

## Consequences

- Two code paths to test and secure, but each serves a distinct network reality.
- Remote updates require two app slots and a stable power supply.
- The current scaffold does not verify the SHA-256 or signature; this is a
  release blocker, not an accepted limitation for production.
- Rollback policy and power-loss testing must be added before fleet rollout.
